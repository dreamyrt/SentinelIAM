# SentinelIAM — Role-Based Access Control (RBAC) & IAM Workspace

SentinelIAM — це демонстраційний веб-застосунок (Portfolio Project) для візуалізації концепцій управління ідентифікацією та доступом (IAM), рольової моделі розмежування доступу (RBAC), двофакторної автентифікації (MFA/TOTP) та систем реального часу для журналювання подій безпеки (SIEM/Audit Logging).

Проєкт розроблено з урахуванням концепції **Zero Trust** (Нульова довіра) та розшарованої моделі захисту (**Defense in Depth**).

---

## 🔑 Особливості реалізації безпеки

1. **Багаторівневий RBAC (Role-Based Access Control)**:
    - Розмежування прав на рівні backend-ендпоінтів за допомогою кастомної залежності FastAPI (`RoleChecker`).
    - Синхронізація ролей у реальному часі: кожний запит до захищеного API примусово перевіряє поточну роль користувача у базі даних SQLite, запобігаючи використанню застарілих привілеїв у токені JWT.
    - Динамічний рендеринг елементів інтерфейсу на основі завантаженого профілю з додатковим захистом на фронтенді (Client-side RBAC Guard).

2. **Двофакторна автентифікація (MFA/2FA)**:
    - Підтримка стандарту RFC 6238 (TOTP) без сторонніх хмарних інтеграцій.
    - Динамічна генерація Base64-код QR-кодів на сервері за допомогою бібліотек `pyotp` та `qrcode` [2].
    - Двокрокова модель авторизації (Challenge-Response) з випуском тимчасових сесійних токенів короткої дії для проходження перевірки 2FA.

3. **Журналювання SIEM Audit Logging**:
    - Ведення детального логу безпеки у базі даних (`AuditLog`) для моніторингу дій користувачів, спроб авторизації та фіксації інцидентів обходу захисту.
    - Логування містить: часову мітку (UTC), пошту ініціатора, подію, IP-адресу клієнта та системний контекст [2].

## 🛠️ Швидкий запуск

Проєкт повністю сумісний із сучасними версіями інтерпретатора, включаючи **Python 3.13**.

### 1. Підготовка віртуального середовища

```bash
# Створення venv
python -m venv .venv

# Активація (Linux/macOS)
source .venv/bin/activate

# Активація (Windows)
.venv\Scripts\activate
```

### 2. Встановлення сумісних залежностей

```bash
# Оновлення утиліт збирання
pip install --upgrade pip setuptools wheel

# Встановлення пакетів
pip install -r requirements.txt
```

### 3. Налаштування логотипа

Помістіть ваше зображення логотипа у корінь проєкту під назвою `logo.png` (поруч із `main.py`).

### 4. Запуск локального сервера

```bash
python main.py
```

Перейдіть у браузері за посиланням: `http://127.0.0.1:8000`.

## 🕵️ Сценарій демонстраційного тестування безпеки

Для демонстрації стійкості захисту SentinelIAM виконайте наступні тест-кейси:

### Тест-кейс 1: Рольове розмежування (RBAC) та клієнтський фільтр

1. Авторизуйтеся як `user@company.com` (роль USER).
2. Переконайтеся, що в бічному меню приховані вкладки Analytics та Access Control.
3. Відкрийте інструменти розробника (F12) і спробуйте виконати прямий запит до закритих даних через консоль браузера:

```javascript
const token = localStorage.getItem("access_token");

fetch("/api/workspace/metrics", {
    headers: { "Authorization": `Bearer ${token}` }
}).then(res => res.json()).then(data => console.log(data));
```

4. Переконайтеся, що запит заблоковано сервером із помилкою 403 Forbidden.

### Тест-кейс 2: Багатофакторна автентифікація (MFA/2FA)

1. У профілі користувача натисніть **Activate MFA**.
2. Відскануйте QR-код мобільним додатком (Google Authenticator) та введіть 6-значний код для підтвердження. Статус зміниться на ACTIVE.
3. Вийдіть із системи (Disconnect) та спробуйте увійти знову.
4. Переконайтеся, що після правильного вводу пароля система переводить вас на другий крок (MFA challenge), не видаючи токен доступу до введення коду з мобільного додатка.

### Тест-кейс 3: Моніторинг та розслідування інцидентів (SIEM/Audit)

1. Авторизуйтеся під акаунтом `admin@company.com` (роль ADMIN).
2. Перейдіть у розділ Access Control.
3. Проаналізуйте таблицю **Real-Time Security Audit Logs**. Знайдіть записи `ACCESS_DENIED_RBAC` зі статусом DENIED для користувача `user@company.com`. Це демонструє, що будь-яка несанкціонована активність фіксується системою SIEM.
4. Змініть роль користувача `user@company.com` на ANALYST у випадаючому списку.
5. Переконайтеся, що при наступному вході або перезавантаженні сторінки цим користувачем йому миттєво відкриється доступ до аналітики без необхідності перевипуску JWT-токенів.

## 📈 Висновки (Conclusions & Security Lessons Learned)

Розробка та архітектурне шліфування SentinelIAM дозволили продемонструвати та закріпити ключові принципи безпечної розробки програмного забезпечення (SSDLC):

2. **Принцип найменших привілеїв (PoLP) та Нульова довіра (Zero Trust):**  
   Приховування елементів керування на фронтенді є лише інструментом покращення UX (User Experience), а не захистом. Надійна безпека SentinelIAM забезпечується на рівні бекенду: кастомні класи-залежності FastAPI здійснюють перевірку JWT-токена та ролі в базі даних при кожному HTTP-запиті. Це повністю нівелює загрози класу BOLA (Broken Object Level Authorization) та спроби прямого звернення до API.

3. **Математична автономія MFA (TOTP):**  
   Проєкт демонструє глибоке розуміння криптографічних протоколів. Завдяки стандарту RFC 6238 додаток на смартфоні користувача та сервер розраховують ідентичні одноразові паролі синхронно, використовуючи лише спільний секрет і поточний час. Це виключає потребу в SMS-шлюзах або постійному інтернет-з'єднанні для автентифікаторів, що робить автентифікацію стійкою до атак класу SIM-Swapping та перехоплення трафіку.

4. **Безперервний моніторинг (SIEM & Observability):**  
   Логування успішних подій важливе для бізнес-логіки, але логування відхилених запитів (DENIED) є критичним для виявлення кібератак. Створення детального аудиту дозволяє ідентифікувати аномальну активність (наприклад, сканування API або спроби перебору ролей) на ранніх етапах розвитку інциденту, забезпечуючи готовність системи до інтеграції з корпоративними SIEM-платформами.
